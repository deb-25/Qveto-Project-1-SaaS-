## 6. Libraries by Layer

### 6.1 Frontend (`frontend/`)

- **Core:** `react`, `react-dom`, `typescript`, `vite`, `react-router-dom`
- **Data & forms:** `@tanstack/react-query`, `axios` (or fetch wrapper), `react-hook-form`, `zod`, `@hookform/resolvers`
- **UI:** `tailwindcss`, `@radix-ui/*` or `@headlessui/react`, `lucide-react` (icons), `clsx`
- **Kanban:** `@dnd-kit/core`, `@dnd-kit/sortable`, `@dnd-kit/utilities`
- **Charts:** `recharts`
- **Dates:** `date-fns` (+ `date-fns-tz`)
- **Testing:** `vitest`, `@testing-library/react`, `@testing-library/user-event`, `msw` (API mocks), `@axe-core/react` or `jest-axe`

### 6.2 Backend (`backend/`)

- **Core:** `express`, `typescript`, `tsx` or `ts-node-dev`, `dotenv`, `zod`
- **Security:** `helmet`, `cors`, `express-rate-limit`, `bcrypt` (or `argon2`), `jsonwebtoken`, `cookie-parser`
- **DB:** `knex`, `pg`
- **Files:** `multer`, `file-type` (MIME sniffing), `uuid`
- **Jobs & email:** `node-cron`, `nodemailer`
- **Logging & docs:** `pino`, `pino-http`, `swagger-ui-express`, `yamljs` (serves `openapi.yaml`)
- **Testing:** `vitest` or `jest`, `supertest`, `@faker-js/faker` (synthetic data)

### 6.3 Storage adapter (DB & Storage owner)

Define an interface so deployment can switch backends without touching business code:

```ts
interface StorageProvider {
  put(key: string, data: Buffer | Readable, meta: { mime: string; size: number }): Promise<void>;
  getStream(key: string): Promise<Readable>;
  delete(key: string): Promise<void>;
}
// Implementations: LocalDiskStorage (dev), S3Storage (deployment)
```

### 6.4 Testing & Quality (root / QA)

- `playwright` (E2E), `@stoplight/prism-cli` (OpenAPI mock server), `eslint`, `prettier`, `husky`, `lint-staged`, `commitlint` (Conventional Commits), `c8`/`vitest --coverage`
- Optional: `k6` or `autocannon` for a light load check; OWASP ZAP baseline scan for the security review.

## 7. Repository & Environment

### 7.1 Required root files

`README.md`, `.env.example` (never real secrets), `.gitignore` (node\_modules, `.env`, `storage/`, `coverage/`, `dist/`), `.nvmrc`, `.editorconfig`, `docker-compose.yml`, `.github/workflows/ci.yml`, `.github/pull_request_template.md`, `docs/decisions.md`, `docs/api/openapi.yaml`.

### 7.2 `.env.example` (starting point)

```
# --- App ---
NODE_ENV=development
PORT=4000
CLIENT_ORIGIN=http://localhost:5173
APP_TIMEZONE=UTC

# --- Database ---
DATABASE_URL=postgres://teamflow:teamflow@localhost:5432/teamflow
TEST_DATABASE_URL=postgres://teamflow:teamflow@localhost:5432/teamflow_test

# --- Auth ---
JWT_ACCESS_SECRET=change-me
JWT_ACCESS_TTL=15m
REFRESH_TOKEN_TTL_DAYS=7
COOKIE_SECURE=false

# --- Storage ---
STORAGE_DRIVER=local            # local | s3
STORAGE_LOCAL_DIR=./storage
MAX_UPLOAD_MB=10
ALLOWED_UPLOAD_TYPES=png,jpg,jpeg,pdf,docx,xlsx,txt,zip

# --- Email (optional) ---
MAIL_MODE=simulated             # simulated | smtp
SMTP_HOST=
SMTP_PORT=
SMTP_USER=
SMTP_PASS=
MAIL_FROM=no-reply@teamflow.local

# --- Jobs ---
OVERDUE_CRON=*/15 * * * *
```

Frontend: `frontend/.env.example` with `VITE_API_URL=http://localhost:4000/api/v1`.

### 7.3 Local setup (target experience, to be scripted in Sprint 0)

```
git clone <repo> && cd teamflow
nvm use                         # Node from .nvmrc
cp .env.example .env && cp frontend/.env.example frontend/.env
docker compose up -d db         # PostgreSQL
npm install                     # root installs both apps
npm run db:migrate && npm run db:seed
npm run dev                     # api on :4000, web on :5173
```

## 9. CI/CD Pipeline (GitHub Actions)

| Stage | Triggers | Steps |
| --- | --- | --- |
| Lint & types | Every PR | `npm ci`, ESLint, `tsc --noEmit` for both apps |
| Unit & API tests | Every PR | Start Postgres service container, run migrations, `npm test`, upload coverage |
| Authz suite | Every PR | `npm run test:authz` (merge blocked on failure) |
| E2E | PR to `main` and nightly | Build apps, start stack, run Playwright, upload report/screenshots |
| Security scan | Weekly + before release | `npm audit --omit=dev`, dependency review |
| Deploy | Push to `main` (or manual) | Build, run migrations, deploy API and frontend, smoke test `/health` |

Branch protection on `main`: PR required, 1–2 approvals, all required checks green, no force-push.

## 14. Cost & Constraints Note

Everything above can be done with **free** tools and free tiers. Free hosting may sleep when idle and may reset local disks, so schedule a warm-up before the final demo, keep a recorded walkthrough and screenshots as backup, and document these hosting limitations in the README and final report.
